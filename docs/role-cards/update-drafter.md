# Role card: the update drafter

KB-137 A1.4. One card per agent. Stage 5's agent, shaped from the message drafter (its guard rules, its data block, its code check of every draft before a person sees it). It reads like a job description: it has an owner, a written brief, limits, and a person who checks its work.

| Item | This agent |
|---|---|
| **Name** | Update drafter (`scripts/draft_updates.py`, started by hand or by `scripts/forecast.py` when the update trigger fires; the engine is [`engine/updates.js`](../../engine/updates.js)) |
| **Purpose** | When an item's 85% date moves by more than a week between two forecast runs (R20), write one short update for each reader from the pipe's data: each requester with an item that moved (every open item of theirs answered, R25), the desk manager, and the executive sponsor (R22) |
| **Named owner** | Systems desk lead: a made-up role in this build. At an employer, the person who owns the desk's communication with the business |
| **What it reads** | One pack of facts per reader, made by code from the store: request ids and titles, the forecast's dates, service level and chances, the lanes' hours, the week's plan, the decide list, the settings that changed. Each fact is a row's value with its source, read by `changedesk.fact_value`, which can read only listed tables and columns. It never sees a request's text, a person's name, a score, or the source of a fact |
| **What it writes** | Nothing. It returns a subject and a body. Code then checks the draft and `changedesk.log_updates` stores it as a draft, with its pack, the figures found in it, how each item is answered, and a who-decided stamp. The store refuses a fact that is not its row's value |
| **What it must never do** | Bring in a figure that is not a fact, or work one out (add, count, average); promise a date; mention scores, lanes, codes, the AI or how the desk works inside to a requester; name or judge a person; repeat contact details; send anything to anyone |
| **Tools** | None. A single Claude Messages call with structured outputs. Model `claude-haiku-5-5`, effort `low` |
| **Brief** | In [`engine/updates.js`](../../engine/updates.js) (`status-update` 1.0.2): six guard rules shared by every audience, then one set of rules for each audience. Its SHA-256 for that audience is logged with every call |
| **Guard rails** | Code, apart from the model ([`engine/figures.js`](../../engine/figures.js), [`engine/updates.js`](../../engine/updates.js)): the pack goes in as escaped JSON inside a data block; every figure in the draft (ids, dates in any form, percentages, money, numbers, numbers in words) is traced to a fact with the same value and unit, or the draft has a problem (R23); a requester's every open item must be named and given its answer: a date range, a service level, the chance of a fixed date with its latest safe start, the week it is planned in, or a named next step (R25); no promise, no internal words, no contact details, no copy of the instructions, within its word limit. A draft with any problem can only be rejected |
| **Approval point** | The n8n form "Change Desk: approve updates". A named person approves or rejects every draft, and sees the row each figure comes from. The store refuses an approval of a draft with problems, of a draft whose facts no longer match their rows, or by one of the build's agents. An approved update goes to `changedesk.outbox`, and nowhere else: nothing in the build sends (R24) |
| **Stop switch** | Nothing is scheduled. It runs only when the forecast is run by hand and the trigger fires, or when `scripts/draft_updates.py` is started. Unpublish the approval form in n8n and nothing can be approved. Revoking the key in the Claude Console workspace `gtm-pipeline` stops every AI call at once |
| **Spend limit** | The workspace `gtm-pipeline` has a US$10 monthly limit. One update costs about US$0.0008 (one drafting run of seven readers, about US$0.005): [`docs/cost-sheet.md`](../cost-sheet.md) |
| **Evidence** | `changedesk.run_log` (step `updater`, one row per call, with the update it drafted), `changedesk.update_triggers` (why it ran), `changedesk.updates` (the draft, its facts, its figures, its problems, its stamp), `changedesk.agent_handoffs` (from the drafter to the person), `changedesk.decisions` and `changedesk.outbox` (the person's decision). `scripts/check_updates.py` reads every figure's row again: [`docs/reports/updates.md`](../reports/updates.md) |
| **How it got to 1.0.2** | Four live runs on one forecast (25/11/2026), every draft kept: 1.0.0 gave 2 clean drafts of 6 (counts written in words; the manager's answer cut off); 1.0.1 gave 6 of 7 twice (the manager's draft over its word limit, then a date that is not a fact); 1.0.2 gave 6 of 7, the seventh flagged by the model itself (a false flag on a requester's "URGENT!!!" title). Runs 1 to 3 were rejected as superseded, on Israel's delegation. There is no labelled eval for it yet: its code checks are its test |
| **Review date** | After COURSES 2ND's test run of the approval form, or sooner if a person rejects an update for a figure or a wording the checks passed |
